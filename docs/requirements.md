# Простой нативный браузер

## 1. Назначение

Плагин предоставляет полноэкранный нативный браузер (WebView) с единообразным внешним видом на iOS и Android. Браузер открывает указанную страницу, поддерживает кастомный пользовательский агент, управление адресной строкой и куками, а также сообщает приложению об ошибках загрузки и событиях навигации.

Плагин заменяет встроенный браузер (`InAppBrowser`) пакета `flutter_inappwebview`: на iOS 15+ тот отображает панели инструментов чёрными из-за несовместимости со схемой настройки внешнего вида панелей (UIBarAppearance). Собственный плагин решает проблему штатными средствами платформы.

Плагин предназначен для работы на устройствах с операционными системами iOS 13 и новее, а также Android (minSdk 26).

## 2. Термины

- **Браузер** — полноэкранное нативное окно с WebView, панелью инструментов и адресной строкой.
- **Адресная строка** — строка, отображающая текущий адрес страницы; может быть скрыта, доступна для редактирования или доступна только для чтения.
- **Постоянное хранилище кук** — хранилище, в котором куки сохраняются между сеансами работы браузера и перезапусками приложения.

## 3. Общие требования

1. Единообразный внешний вид и поведение на iOS и Android.
2. Поддержка светлой и тёмной темы в соответствии с настройками устройства; тема применяется автоматически, ручной переключатель не требуется.
3. Поддержка книжной и альбомной ориентации, а также адаптивной вёрстки для планшетов.
4. Панели инструментов окрашиваются в системные цвета темы; на iOS используются обычные UIView с системными цветами, исключающие появление чёрных панелей.
5. Плагин не должен препятствовать работе механизмов доверия сертификатам, действующих в приложении; специальная поддержка со стороны плагина не требуется.

## 4. Функциональные требования

### 4.1. Открытие браузера

1. Плагин открывает полноэкранный браузер с указанным стартовым адресом.
2. Браузер можно открывать многократно; после закрытия ресурсы освобождаются, утечки памяти не допускаются. Одновременно может быть открыт только один браузер: повторное открытие при активной сессии управляется функцией решения, возвращающей действие (отбрасывание, замена обработчиков, применение настроек, полная замена с перезагрузкой страницы).

### 4.2. Пользовательский агент

1. Плагин позволяет задать произвольный пользовательский агент (User-Agent) для WebView.
2. Если пользовательский агент не задан, используется стандартный пользовательский агент платформы.

### 4.3. События навигации и ошибки загрузки

1. Плагин сообщает приложению об ошибке загрузки страницы, передавая адрес, на котором произошла ошибка (обработчик onLoadError).
2. Плагин сообщает приложению об успешном завершении загрузки страницы, передавая адрес (обработчик onLoadStop).
3. Плагин сообщает приложению о попытке открыть адрес с кастомной схемой, передавая этот адрес (обработчик onSchemeRedirect); такие адреса не передаются как ошибка загрузки.
4. Плагин только передаёт события приложению; обработку адресов выполняет приложение.

### 4.4. Закрытие браузера

1. Кнопка закрытия (крестик) располагается в левом верхнем углу верхней панели на обеих платформах.
2. Плагин предоставляет метод close() для закрытия браузера из кода приложения.
3. При закрытии браузера (кнопкой, системной кнопкой «Назад» или методом close()) плагин уведомляет приложение через обработчик onClosed.

### 4.5. Адресная строка

1. Адресная строка поддерживает три режима:
   - скрыта;
   - отображается и доступна для редактирования (позволяет перейти на введённый адрес);
   - отображается, но доступна только для чтения.

### 4.6. Панели инструментов

1. Верхняя панель содержит кнопку закрытия, заголовок страницы и адресную строку (в зависимости от выбранного режима).
2. Нижняя панель содержит кнопки навигации: «Назад», «Вперёд», «Обновить».
3. Кнопки «Назад» и «Вперёд» недоступны (отключены), если переход в соответствующем направлении невозможен на текущей странице.
4. Кнопки отображаются в виде иконок, без текстовых подписей.

### 4.7. Куки

1. Плагин позволяет передать набор начальных кук, которые устанавливаются до загрузки стартовой страницы.
2. Плагин предоставляет метод reloadWithCookies: устанавливает переданные куки и перезагружает текущую страницу.
3. Режим постоянного хранилища управляется флагом usePersistentCookieStore:
   - при значении true куки сохраняются между перезапусками приложения и сеансами браузера (режим по умолчанию);
   - при значении false используется эфемерный режим: на iOS куки не сохраняются после закрытия браузера (изолированное non-persistent хранилище); на Android хранилище кук общее для процесса, поэтому эфемерный режим очищает общие куки при открытии браузера, а куки сеанса остаются в общем хранилище после закрытия — до следующего открытия в эфемерном режиме или ручной очистки приложением.

### 4.8. Параметры WebView

1. Плагин позволяет отключить приём и передачу кук (параметр enableCookiesAndroid, значение по умолчанию true). Параметр действует только на Android: отключение применяется к процессу целиком и снимается при закрытии браузера; на iOS куки не отключаются.
2. Плагин позволяет разрешить загрузку локальных файлов (параметр allowFileAccess, значение по умолчанию false). При false адреса file:// не загружаются на обеих платформах и передаются приложению через onSchemeRedirect; при true загрузка локальных файлов доступна.
3. Значения name, value, domain и path передаваемых кук проверяются: символы «;», «,» и управляющие символы запрещены (защита от инъекции атрибутов кук).

### 4.9. Скачивание файлов

1. При попытке пользователя скачать файл (например, ссылка с Content-Disposition: attachment или бинарный контент) плагин вызывает обработчик onDownloadStart и передаёт ему адрес файла.
2. Загрузка не является функцией браузера: переход на файл отменяется (страница не заменяется бинарным контентом), скачивание выполняет клиентское приложение.
3. onDownloadStart доступен на обеих платформах. На iOS адрес доставляется через WKDownload (iOS 14.5+) либо эвристику по MIME-типу ответа главного кадра (iOS 13–14.4); на Android — через DownloadListener.

## 5. Требования к интеграции

1. Плагин заменяет встроенный браузер InAppBrowser; остальные WebView приложения не затрагиваются.
2. Публичный API плагина:
   - метод open — открытие браузера (стартовый адрес, пользовательский агент, режим адресной строки, флаг постоянного хранилища кук, флаг режима отладки, начальные куки, обработчики событий);
   - повторное открытие при активной сессии: функция решения, получающая старый и новый запросы и возвращающая действие (отбрасывание, замена обработчиков, применение настроек, полная замена с перезагрузкой);
   - метод close — закрытие браузера;
   - метод reloadWithCookies — установка кук и перезагрузка страницы.

## 6. Ограничения и допущения

1. На Android хранилище кук является общим для всех WebView приложения: эфемерный режим очищает общие куки при открытии браузера и может завершить сеансы других WebView; куки эфемерного сеанса остаются в общем хранилище после закрытия браузера. На iOS эфемерный режим использует изолированное хранилище и не влияет на другие WebView.
2. Плагин не ограничивает ориентацию и не устанавливает собственные ограничения манифеста; ограничения, заданные приложением, сохраняются.

## 7. Критерии приёмки

1. Браузер открывается с указанным адресом и кастомным пользовательским агентом.
2. В светлой и тёмной теме панели инструментов окрашены корректно (без чёрных полос).
3. Адресная строка корректно работает во всех трёх режимах.
4. Кнопки «Назад» и «Вперёд» отключаются, когда переход невозможен; «Обновить» перезагружает страницу.
5. Закрытие браузера любым способом приводит к вызову onClosed; повторное открытие работает без сбоев и утечек.
6. Начальные куки установлены до загрузки страницы; reloadWithCookies устанавливает куки и перезагружает страницу.
7. При включённом постоянном хранилище куки сохраняются между сеансами, при выключенном — не сохраняются.
8. События onLoadError, onLoadStop и onSchemeRedirect вызываются корректно и передают адрес страницы.
9. При попытке скачать файл вызывается onDownloadStart с адресом файла, навигация на файл отменяется.
10. При allowFileAccess=false адреса file:// не загружаются и передаются через onSchemeRedirect; при enableCookiesAndroid=false на Android куки не принимаются и после закрытия браузера приём кук возвращается в исходное состояние.
